# ADR-0002:封閉貢獻模型 —— 不開放 issue / PR / fork

- **狀態**:已接受(Accepted,2026-09-05)
- **決策者**:CL0/R0(cl0r0)維護者
- **日期**:2026-09-05
- **相關文件**:`CONTRIBUTING.md`、`docs/ARCHITECTURE.md`、`docs/STATUS-ASSESSMENT-*.md`

---

## 背景(Context)

大多數開源專案透過公開 issue / PR / fork 來聚集社群貢獻。但 cl0r0 有兩個特質使其**反模式**:

1. **正確性由機器擔保,而非社群審查**。接納契約是 `ci.yml` 的四道閘 + reconcile 的逐點對帳 +
   `Print Assumptions` 缺 Axiom。這些**不依賴人類審查**,開放討論無法提高正確性,只會增加雜訊。
2. **供應鏈與治理風險**。公開 PR / fork 引入外部代碼、依賴與意見,破壞「可證件載體」的封閉可追溯性;
   且本專案以「定律為真」為目標,任何未經 kernel 驗證的變更都可能是**捷徑為假**的來源。

## 決策(Decision)

**本庫封閉**:不開放 **issue**,不處理 **PR**,不接受 **fork 回送**。

* 變更**只**來自:(a)內部維護者直接推送;(b)第一方自動化(Dependabot 依賴升級、Workflow bot 提交)。
* 外部人員可 **fork / 參考 / 學習 / 自建驗證**,但**不得**將變更回送上游,也不得假設會被合併。
* 對安全/正確性問題,採**私下通道**(Security advisories / private vulnerability report,或指定郵箱),
  以「最小重現 + 預期 vs 實際」交付證據。

## 後果(Consequences)

**正面**
- 可追溯、低雜訊、供應鏈面收窄;「定律為真」不被未驗證變更稀釋。
- CI 成為**單一**驗收契約,無「社群審查」這一不確定依賴。

**反面 / 成本**
- 失去社群眾包的好處(多樣化視角、第三方 review)。以「區間圖/弦圖/完美圖」等可證明的性質
  彌補 —— 任何「反例」可被**機器**驗證,而非靠人。
- 需要一個明確定義的隱私通道(§背景 2),否則會把真實 bug 擋在門外。

**例外/豁免**
- Dependabot 屬**第一方自動化**,其依賴升級 PR 是**唯一** PR 來源,非外部貢獻(見 `CONTRIBUTING.md` §1)。

## 覆核(Review)

- 2026-09-05:與 `CONTRIBUTING.md`、`docs/adr/0001`(雙載體,CI 為唯一驗收)一致。
- 若要重新開放,應先建立「如何相容於 kernel 驗證 + reconcile」的外部貢獻管道(暫無此計畫)。
